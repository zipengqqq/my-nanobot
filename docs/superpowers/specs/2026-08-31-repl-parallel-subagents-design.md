# REPL 并行子 Agent 批次委派设计

## 目标

为 `my_agent` 的终端 REPL 增加由主 Agent 按需调用的并行子 Agent 批次委派能力。主 Agent 仅在复杂任务能够拆分为多个互不依赖的子任务时调用该能力；普通问答和单一连续任务继续走现有 `AgentLoop -> AgentRunner` 调用链。

调用后，REPL 立即显示任务已分派，用户可继续输入。子 Agent 并行运行，每项完成时显示进度。整批任务都结束后，系统将受限后的结果写入当前会话，并在前台空闲时自动调用一次主 Agent 汇总后回复用户。

## 范围

本次仅修改 `my_agent/` 及其回归测试，保留终端 REPL 作为唯一产品入口。不会引入 WebUI、聊天渠道、网关、跨进程任务恢复或长期任务面板。

不复用 `nanobot/` 和 Hermes 的大型消息总线、持久化队列或异步框架；仅借鉴其“批次作为一个后台单位、整批完成后只回流一次”的编排语义。

## 架构

新增批次协调器，由 `SubagentManager` 或其专用协作者管理。它维护进程内批次状态：批次标识、所属会话、任务描述、每项状态、截断后的结论、失败摘要和完成计数。

主 Agent 通过新的 `spawn_subagents(tasks)` 工具一次提交一组独立任务。该工具立即返回批次标识与分派摘要，不等待执行结果。协调器通过受限的线程池并行运行子 Agent，每个子 Agent 仍使用独立上下文、独立工具注册表和既有工作区 Sandbox。

协调器向线程安全事件队列写入两类事件：单项完成事件和整批完成事件。REPL 消费单项事件并输出任务进度；整批完成事件只在当前前台轮结束后处理，避免并发读写同一会话或终端输出交错。

```text
用户输入 -> AgentLoop -> AgentRunner
                       -> spawn_subagents(tasks)
                       -> 后台批次协调器 -> 最多 N 个子 Agent
REPL <- 单项完成事件 <- 子 Agent 结果
REPL <- 整批完成事件 <- 所有子 Agent 均结束
     -> SessionManager 持久化批次摘要
     -> AgentLoop 内部汇总轮 -> 最终回复
```

## 交互与会话

REPL 在成功分派后立即显示主 Agent 的当前回复，用户可继续输入。每个任务结束时显示任务序号、简短标签和成功或失败状态。子 Agent 的原始工具调用记录和完整输出不显示，也不写入会话。

整批完成后，REPL 将全部子任务的任务描述、状态、截断结论或错误摘要组织为一条内部批次结果。该记录写入当前会话历史，并作为受控内部上下文触发主 Agent 进行一次汇总。内部批次结果不是用户消息，避免模型把它误解为用户的新指令。

如果 REPL 此时正在处理用户的新输入，批次汇总等待该前台轮结束；之后按完成顺序处理待汇总批次。最终主 Agent 回复和内部批次记录都被持久化，因此下一次对话可以引用已完成任务的结论。

## 调度与安全边界

默认最多并行三个子 Agent，通过 `MY_AGENT_MAX_CONCURRENT_SUBAGENTS` 配置并由 Pydantic 验证范围。单个子 Agent 有超时限制和结果最大长度限制。任务列表必须非空，任务数不得超过允许上限，并过滤无效或重复任务。

仅当主 Agent 明确调用 `spawn_subagents` 才会分派任务。工具提示应要求：至少两个彼此独立的子任务、无任务间依赖、且不同时修改同一文件；无法确信满足条件时不得委派。普通任务不会自动进入多 Agent 流程。

子 Agent 不注册批次委派工具，不能递归创建新的子 Agent。它们沿用现有文件路径允许目录、Shell Sandbox、联网验证和结果截断边界。批次状态不记录密钥、完整工具原始输出或不必要的本地路径。

单项失败或超时只形成该项失败摘要，不取消其余任务，也不阻止最终汇总。协调器自身异常导致批次无法完成时，写入失败内部记录并触发一次主 Agent 说明结果。REPL 收到 `quit`、`exit`、`Ctrl+C` 或 EOF 时取消仍在运行的批次并等待收尾，避免关闭后继续输出。

## 验证

为新增协调器、工具、REPL 事件消费和会话写入增加 `my_agent` 回归测试，至少覆盖：

- 任务并行执行与并发上限。
- 单项成功、异常和超时，以及所有任务结束后才发出一次批次完成事件。
- 单项完成提示和批次汇总只触发一次主 Agent 汇总轮。
- 前台轮执行期间延迟批次汇总，确保会话历史串行写入。
- 内部批次记录与最终回复正确持久化。
- REPL 退出时取消未完成任务。

实现后运行相关 `pytest`、`ruff check my_agent/`，并手动验证 REPL 的启动、空输入、`quit`/`exit`、`Ctrl+C`、EOF 和后台批次交互。
